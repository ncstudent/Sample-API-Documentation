Catalog API / Getting started

Getting started

Version 1.3.0

This guide sets up the Sample Catalog API for local development and confirms that it can respond to a request.

Prerequisites

  • Node.js 18 or later
  • MongoDB 7.0 or later, running locally or reachable over the network
  • Access to the project repository
  • A MongoDB user with read and write permissions on the Catalog database

Install

  1. Clone the repository using the URL provided with your project access, then change into the project directory.
  2. From the directory that contains package.json, install the dependencies: 
    npm install

Configure the environment

The API reads two environment variables at startup.

VariableRequiredDescription
MONGO_URINoMongoDB connection string. Defaults to mongodb://localhost:27017. Set it when using another host or credentials.
API_TOKENYesThe bearer token that clients must send. There is no default.

For local development, set both variables in the shell that starts the server:

export MONGO_URI="mongodb://localhost:27017"
export API_TOKEN="dev-token"
npm start
Development credential onlydev-token is an example value for local use. In any shared or deployed environment, use a long random secret and keep it out of source control.

Set up the database

The API uses the items collection in the Catalog database. At startup, connect() creates a unique ascending index on catalogId. ID generation also writes to a counters collection (see Catalog ID generation), so the database user must be able to create and update both collections.

Start and verify the API

Run npm start. The server listens on http://localhost:3000. With the example configuration, request one item using the dev-token value set in API_TOKEN:

curl -i \
  -H "Authorization: Bearer dev-token" \
  "http://localhost:3000/api/v1/items?page=1&limit=1"

A successful request returns 200 OK with a JSON object containing results, page, limit, and total. On an empty database, results is an empty array.

Authentication

Every endpoint requires a bearer token. Clients send the value of API_TOKEN in the Authorization header:

Authorization: Bearer <API_TOKEN>

With the example configuration, the header is Authorization: Bearer dev-token. The API has no endpoint for creating tokens; the operator sets the token at startup. The optional AuthInit.sh script can set up the local demonstration token, but it is not needed if you export API_TOKEN yourself.

Use the API in Postman

  1. Select Import and choose Catalog.postman_collection.json from the project's docs directory.
  2. Create an environment, such as Local Catalog API, with two variables: baseUrl set to http://localhost:3000/api/v1 and token set to the value of API_TOKEN.
  3. Select that environment. On the collection, set the Authorization type to Bearer Token with the value {{token}}.
  4. Open the create-item request, use the body below, and select Send.
POST {{baseUrl}}/items
Authorization: Bearer {{token}}
Content-Type: application/json

{
  "title": "Sales CRM Onboarding Workshop Slides",
  "type": "training",
  "owner": "Learning and Development",
  "tags": ["onboarding", "slides"]
}

A valid request returns 201 Created with the new item, including a generated catalogId, a status of draft, and server-generated timestamps.

Troubleshooting

ResultLikely causeResolution
401 UnauthorizedThe token is missing or differs from the server's API_TOKEN.Check the selected environment, the token value, and the Bearer Token setting.

For other status codes, see the error reference.

Catalog API / Guides

Data layer

Version 1.3.0

The data layer stores each catalog item as a MongoDB document. It defines the item schema, generates catalog IDs, and implements the MongoDB operations called by the API routes.

For Node.js, MongoDB, and database permission requirements, see Getting started.

Document structure

Dates are stored as BSON dates and returned as ISO 8601 strings in JSON.

FieldTypeRequired in requestDefaultDescription
catalogIdstringNo (generated)—Unique ID in the form CAT-0001, generated from an atomic sequence.
titlestringYes—Display name of the item.
typestringYes—Item category: ip or training.
ownerstringYes—Team or person responsible for the item.
descriptionstringNo""Short summary of the item.
tagsarray of stringsNo[]Labels for grouping and search.
statusstringNo"draft"Lifecycle state: draft, active, or archived. Always stored.
createdAtdateNo (generated)Time of insertCreation time. Kept when an item is replaced.
updatedAtdateNo (generated)Time of writeTime of the latest create or replace.

Database connection

db.js
const { MongoClient } = require('mongodb');

const client = new MongoClient(
  process.env.MONGO_URI || 'mongodb://localhost:27017'
);

let items;
let counters;

async function connect() {
  await client.connect();
  const db = client.db('Catalog');
  items = db.collection('items');
  counters = db.collection('counters');

  await items.createIndex({ catalogId: 1 }, { unique: true });
  return { items, counters };
}

module.exports = {
  connect,
  collection: () => items,
  counters: () => counters
};

Call connect() once at startup, before the server accepts requests. The shared MongoClient keeps a connection pool, so do not create a new client for each request.

Catalog ID generation

Each ID comes from a counter document that MongoDB increments atomically with $inc, so concurrent requests never receive the same number. The unique index on catalogId acts as a backstop. Deleting an item does not free its number, so IDs reflect creation order, not the current record count.

db.js
async function nextCatalogId() {
  const result = await counters.findOneAndUpdate(
    { _id: 'catalogId' },
    { $inc: { seq: 1 } },
    { upsert: true, returnDocument: 'after' }
  );

  // Supports both the ModifyResult and direct-document driver return shapes.
  const counter = result && result.value ? result.value : result;
  if (!counter || typeof counter.seq !== 'number') {
    throw new Error('Unable to allocate a catalog identifier');
  }

  return `CAT-${String(counter.seq).padStart(4, '0')}`;
}

The first increment produces CAT-0001. If MongoDB reports duplicate-key error 11000, the route returns 409 Conflict with the duplicate_catalog_id error. A duplicate means the counter has fallen behind the stored data. Investigate it; retrying will not fix it.

Migrating an existing databaseBefore enabling the counter on a database that already holds items, set seq to the highest existing numeric suffix so the next ID does not collide. For example, if the highest ID is CAT-0042:
db.counters.updateOne({ _id: 'catalogId' }, { $set: { seq: 42 } }, { upsert: true })

Create an item

async function createItem({
  title,
  type,
  owner,
  description = '',
  tags = [],
  status = 'draft'
}) {
  const now = new Date();
  const catalogId = await nextCatalogId();
  const doc = {
    catalogId,
    title,
    type,
    owner,
    description,
    tags,
    status,
    createdAt: now,
    updatedAt: now
  };

  await items.insertOne(doc);
  return doc;
}

The route validates required fields and allowed values before calling this function. Omitted description, tags, and status take the defaults shown.

List items

async function listItems({ type, page = 1, limit = 20 }) {
  const filter = type ? { type } : {};
  const [results, total] = await Promise.all([
    items.find(filter)
      .sort({ createdAt: -1 })
      .skip((page - 1) * limit)
      .limit(limit)
      .toArray(),
    items.countDocuments(filter)
  ]);

  return { results, page, limit, total };
}

Results are sorted by createdAt, newest first. The function accepts an optional type filter and page-based pagination. It does not filter on status.

Replace an item

findOneAndReplace() swaps in a new document instead of merging fields, so any field left out is removed. replaceItem() therefore writes every field explicitly. It reads the existing createdAt first and keeps it, sets updatedAt to the current time, and resets an omitted status to draft. If the item does not exist, it returns null and the route responds 404 Not Found.

async function replaceItem(catalogId, {
  title,
  type,
  owner,
  description = '',
  tags = [],
  status = 'draft'
}) {
  const existing = await items.findOne(
    { catalogId },
    { projection: { createdAt: 1 } }
  );

  if (!existing) return null;

  const result = await items.findOneAndReplace(
    { catalogId },
    {
      catalogId,
      title,
      type,
      owner,
      description,
      tags,
      status,
      createdAt: existing.createdAt,
      updatedAt: new Date()
    },
    { returnDocument: 'after' }
  );

  // Older driver versions wrap the document in result.value.
  return result && Object.prototype.hasOwnProperty.call(result, 'value')
    ? result.value
    : result;
}

Delete an item

async function deleteItem(catalogId) {
  const { deletedCount } = await items.deleteOne({ catalogId });
  return deletedCount === 1;
}

deleteOne() permanently removes the document. The function returns true if a document was deleted and false if the ID does not exist. The route responds 200 OK with a confirmation, or 404 Not Found. Unexpected database failures return 500 Internal Server Error.

API reference

Version 1.3.0

All endpoints are under the /api/v1 base path, require a bearer token, and return JSON. Any endpoint can also return 401 (missing or invalid token) or 500 (unexpected failure); the endpoint sections list only the other errors. For token setup, see Getting started.

Replace an item

PUT /api/v1/items/:catalogId

Replaces the whole item. The body takes the same fields as Create an item. Any optional field you omit resets to its default, including status, which resets to draft. The server keeps the original createdAt, sets updatedAt to the time of replacement, and drops fields outside the schema.

Example request

PUT /api/v1/items/CAT-0042
Authorization: Bearer <token>
Content-Type: application/json

{
  "title": "Updated Sales CRM Workshop",
  "type": "training",
  "owner": "Learning and Development",
  "description": "Revised workshop materials.",
  "tags": ["onboarding", "revised"],
  "status": "archived"
}

Example response — 200 OK

{
  "catalogId": "CAT-0042",
  "title": "Updated Sales CRM Workshop",
  "type": "training",
  "owner": "Learning and Development",
  "description": "Revised workshop materials.",
  "tags": ["onboarding", "revised"],
  "status": "archived",
  "createdAt": "2025-03-04T14:22:10.000Z",

Errors: 400 invalid_parameters for a missing or invalid field; 404 not_found if no item has that ID.

Add a status field

Version 1.3.0

This tutorial adds the status field to catalog items, as released in version 1.3.0. The change touches the field definition, the create and replace functions, request validation, the tests, and the API reference. The snippets show only the lines that change; the complete functions are in the data layer guide.

1. Define the allowed values

Keep the allowed values and the default in one place.

const allowedStatuses = ['draft', 'active', 'archived'];
const defaultStatus = 'draft';

2. Store the field on create

Add status to the createItem() input with the default, and include it in the inserted document. Keep generating IDs with nextCatalogId(). Deriving them from countDocuments() + 1 reuses IDs after deletions and produces duplicates under concurrent requests.

async function createItem({
  title, type, owner, description = '', tags = [],
  status = defaultStatus
}) {
  // Keep the existing ID and timestamp generation.
  const now = new Date();
  const catalogId = await nextCatalogId();

  const doc = {
    catalogId, title, type, owner, description, tags,
    status,
    createdAt: now,
    updatedAt: now
  };

  // Keep the existing insert and return logic.
}

3. Validate requests

Apply the default first, so an omitted status passes as draft. Reject any other value with 400 and invalid_parameters before anything is written to MongoDB.

routes/items.js
const { status = defaultStatus } = req.body ?? {};

if (!allowedStatuses.includes(status)) {
  return res.status(400).json({
    error: 'invalid_parameters',
    message: 'status must be draft, active, or archived'
  });
}

4. Write the field on replace

PUT replaces the whole document, so replaceItem() must write status explicitly, with the same default as create. If a request omits it, the item goes back to draft.

async function replaceItem(catalogId, {
  title, type, owner, description = '', tags = [],
  status = defaultStatus
}) {
  const existing = await items.findOne(
    { catalogId },
    { projection: { createdAt: 1 } }
  );
  if (!existing) return null;

  const replacement = {
    catalogId, title, type, owner, description, tags,
    status,
    createdAt: existing.createdAt,
    updatedAt: new Date()
  };

  // Pass replacement to findOneAndReplace().
}

5. Test the field

Three cases matter: a new item defaults to draft, an unsupported value is rejected, and a replacement that omits status resets it to draft. The examples use the project's existing app instance and request helper.

it('defaults a new item to draft', async () => {
  const res = await request(app)
    .post('/api/v1/items')
    .set('Authorization', 'Bearer test-token')
    .send({ title: 'Example', type: 'training', owner: 'L&D' });

  expect(res.status).toBe(201);
  expect(res.body.status).toBe('draft');
});

it('rejects an unsupported status', async () => {
  const res = await request(app)
    .post('/api/v1/items')
    .set('Authorization', 'Bearer test-token')
    .send({ title: 'Example', type: 'training', owner: 'L&D', status: 'pending' });

  expect(res.status).toBe(400);
  expect(res.body.error).toBe('invalid_parameters');
});

it('resets status to draft when a replacement omits it', async () => {
  const created = await request(app)
    .post('/api/v1/items')
    .set('Authorization', 'Bearer test-token')
    .send({ title: 'Example', type: 'training', owner: 'L&D', status: 'active' });

  const replaced = await request(app)
    .put(`/api/v1/items/${created.body.catalogId}`)
    .set('Authorization', 'Bearer test-token')
    .send({ title: 'Replaced', type: 'training', owner: 'L&D' });

  expect(replaced.status).toBe(200);
  expect(replaced.body.status).toBe('draft');
  expect(replaced.body.createdAt).toBe(created.body.createdAt);
});

6. Update the API reference

Document status as an optional field in the POST and PUT request schemas, including its allowed values and draft default. Include it in the example responses. List responses also include the field, but GET /items does not support a status filter.
